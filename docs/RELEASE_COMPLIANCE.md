## LGPL 与 APK 分发

- “不是逐文件翻译”可以描述技术实现，但不是自动免责或消除衍生关系的法律标准。可保护表达是否被复制／改编，需要结合代码和具体法律判断。
- LGPL 通常允许商业使用，不能仅凭 README 中的 personal use 表述自行给标准许可加限制；但该表述与权利人意图仍需澄清，不应在未澄清时向他人承诺无争议商用。
- 保留 LGPLv3 和其引用的 GPLv3 全文，保留适用的版权通知、注明修改，并提供与发布二进制对应的源代码、构建脚本、依赖版本及必要资料。
- 按实际修改、组合与链接方式评估 LGPLv3 的对应源码、重新组合／重新链接、反向工程许可等要求；适用时还涉及安装信息。公开一个源码仓库本身不一定满足每一种 APK 分发情形。
- 不把库链接问题简单等同于整个迁移项目的许可归属；当前工程主动保留上游许可基线，不作其可以闭源或可重新许可为 MIT 的结论。
- 构建产物、签名与发布版本应可追踪到相应源码；不要把个人签名私钥提交到仓库。
